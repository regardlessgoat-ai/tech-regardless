The hard part was never displaying a menu. It's that the customer is a restaurant with
nobody on staff to babysit software. Anything that needs maintaining is a tool that quietly
stops being used, so every decision came back to one question: can the owner do this from a
phone between lunch and dinner?

The sixteen card styles are genuinely different layouts, not recolours, and the list of
valid styles lives in **one allowlist enforced identically on the server and in the browser.**
That seam is where these systems usually rot: a style ships in the picker, the API rejects it,
and a restaurant saves a menu that renders as nothing.

Translation covers thirty-five languages, cached so the same dish is never paid for twice,
with a food glossary so *carne asada* doesn't come back as "grilled meat." Every theme's font
stack ends in a shared fallback chain carrying Noto CJK and Noto Arabic, so a diner reading
Japanese never sees a page of empty boxes.
